## 4. Key decisions (details in `docs/adr/README.md`)
- Pixi v8 world in a low-res target (320–400 px) + React DOM UI (001); pure core, one analytic `advance()` (002); Capacitor web-first, no backend (003).
- All pixel art by code: material generators + palette quantization + art-director gate (004); music/ambience synthesized, physical modelling (005).
- Rewarded ads only, UMP, caps in core (006, superseded in part by 010). Shop (010, SPEC v1.3 §4): pysanky = the one premium currency (earned ≈ 20/day + sold), ad-free = instant rewards under the same caps, capped convenience + cosmetics, never regalia/power; bounds ads ≤ 1.5×, payer ≤ 1.75× (`pnpm balance --profile`); Play Billing via `StoreService` (cdv-purchase recommended), on-device verification v1, entitlements re-queried from Play, never trusted from saves. Quests SPEC §3.10: chain «Наказ кошового» + chores M2, daily/weekly M6. CLAUDE.md ad rule needs "or `noAds`" (owner). Settlement = farm + suburb + Sich, kharch/defence links; lands = Host's path Khortytsia → Nova Sich (007).
- Names: «Козацький хутір» / «Cossack Kin»; applicationId `com.cossackkin.game` (fixed at first Play upload).
- Pacing & variety (009, accepted 2026-11-19; SPEC v1.2 §2.4–2.6; v1 ≈ 3–4 months, +30 %/land): novelty every session in week 1, daily after — measured by `pnpm balance` from `content/pacing.ts` (`novelty`, `calendar`; M1-14 logs only M1 systems); story beats `content/story.ts` (M2, save v2); variety only from seed + time (visitors M2/M6, daily news / fair good / weather economy M6, raid board M3).
- Toolchain & supply chain (008): TS ~6.0.3, exact versions, pnpm no build scripts + 3-day release age, SHA-pinned CI on ubuntu-26.04, strict CSP, `pnpm security`.

## 6. Gotchas / learned the hard way
_(append one line per non-obvious discovery: what, where, why)_
- Balance: with SPEC §3.2 numbers and no modifiers a greedy bot reaches bloom of village 1 in ~2.8 days (target 4–6) — see `SPEC-REVIEW.md` B-01. Do not trust the table until `balance-sim` exists.
- 2026-11-19: the machine moved to Node 26.13.1 (no corepack): pnpm 12.21.0 is now a plain `npm i -g pnpm@12.21.0` install (its postinstall is skipped by npm's allow-scripts; not needed). CI stays on Node 24 — `engines` is `>=24`.
- pnpm 12.21.0 is on PATH; `corepack enable` fails with EPERM (Program Files) — don't retry. `packageManager` is pinned in package.json. pnpm 12 prints "Agent skills awaiting approval: pixi.js" on install — harmless, `pnpm approve` is optional.
- Node 24 runs `tools/*.ts` directly (built-in type stripping, no warning) — no `tsx`. Tools code must stay erasable-only (`erasableSyntaxOnly`: no enums/namespaces/param properties) and import with `.ts` extensions.
- TypeScript pinned `~6.0.3`: typescript-eslint 8.72 needs `<6.1.0`; TS 7 has no JS API until 7.1 (plan R5).
- ESLint core-purity rules mirror `.claude/hooks/core-purity.mjs`; messages are tagged `core-purity[<rule>]` and `tests/unit/lint/core-purity.test.ts` checks the fixture line by line. The test lints a virtual `src/core/…` path, so it applies `disableTypeChecked` (project service can't see unsaved files).
- `local/require-disable-reason` (eslint.config.js) allows only `eslint-disable-next-line <rule> -- <reason>`; a file-wide `/* eslint-disable */` still silences the report about itself — catch it in review.
- Prettier ignores `*.md`, `docs/`, `.claude/`, `.github/ISSUE_TEMPLATE/` (hand-authored); the format hook respects `.prettierignore`.
- `computeViewport`: 401–639 device px yields logical width < 320 (×2) — the 400 cap wins by design (Q2).
- Windows dev machine: hooks are Node scripts (no bash/jq). Git Bash heredocs with quotes break — use the Write tool or script files.
- WebGL in Playwright: `--use-angle=swiftshader --enable-unsafe-swiftshader` (playwright.config.ts). On Windows headless shell already picks ANGLE/Vulkan SwiftShader without them; kept explicit for Linux CI. Never `--disable-gpu`. Specs assert a WebGL context + `__CK__.stats.drawCalls` before any pixel check. Freeze (`?freeze`) for stable shots.
- E2E serves a `--mode test` build from `dist-test/` (not `dist/`, so `pnpm check:dist` keeps checking prod). `reuseExistingServer` is on locally — kill a stale :4317 preview after source changes.
- 412×915@3.5: viewport height 3202.5 device px → screenshot has 3203 rows and the last one is a compositor blend. The pixel-grid check covers floor(css × dpr) px only. Pixel grid = no color edge inside a `scale×scale` block, column phase −frac(cam) (`tests/e2e/helpers/pixelGrid.ts`); PNGs are read/written by a tiny `node:zlib` codec (`tools/lib/png.ts`, 8-bit RGB/RGBA only), no PNG dependency (owner: small supply chain — `pngjs` from plan §1 dropped).
- `toHaveScreenshot` baselines are compared only when `process.platform === 'linux'` (snapshots under `tests/e2e/__screenshots__/`, `{platform}` in the name); Windows/macOS only write `reports/screens/` artifacts. No Linux baselines yet — see CI below.
- Playwright MCP (`.mcp.json`) runs `pnpm exec playwright run-test-mcp-server` (pinned via lockfile; `cmd /c` wrapper on Windows).
- Debug gate: `__CK_DEBUG__` (vite `define`, allowlist `isDebugMode` = development | test in `render/debug/modes.ts`, shared with `parseDebugParams`; declared in `src/env.d.ts`, `true` in vitest). Debug-only code must sit behind it so Rolldown drops it; `RenderSettings` field names are neutral (`frozenAt`, not `freeze`) because property names survive minification. A plain `grep freeze dist/` is always non-empty (Pixi `Object.freeze`): `pnpm check:dist [dir]` (`tools/lib/dist-leaks.ts`) matches the quoted key `"freeze"`/`` `freeze` `` (Rolldown emits backtick literals), `location.search`/`URLSearchParams`, `__CK__`, `debug-overlay`, `sourceMappingURL` and `*.map` files; positive control: `node tools/check-dist.ts <test-mode outDir>` must fail.
- Frame order on `app.ticker`: debug begin (HIGH) → world → worldRT (NORMAL) → Application stage render (LOW) → debug end + `data-ready` (UTILITY). Draw counter wraps the GL context's `draw*` methods; M0 scene = 3 draw calls.
- `camera.split` rounds `camX·scale` to whole device px (`Math.round`, ties toward +∞): `cam=0.5` at ×3 → 2 device px; −0.25 at ×2 → 0. Sky (parallax 0) still moves by the device-px remainder — the remainder is applied to the whole upscale sprite by design.
- worldRT = `worldTargetSize` = ceil(device/scale) + 1 (not logicalW + 1: gap at the right edge when deviceW mod scale ≥ 2); camera bounds use ceil(deviceW/scale); each layer draws `contentWidth(parallax, size)`. Global CSS lives in `src/ui/global.css` (no inline `<style>`, CSP M0-12); host background from the palette.
- worldRT is `dynamic: true` so the upscale Sprite follows `RenderTexture.resize`; the Pixi canvas is created by Pixi (not reused) so React StrictMode double-mount can destroy the first app safely.
- Headless Edge/Chrome CLI `--screenshot --window-size=390,844` on Windows lays out at ≈ 480–500 css px (minimum window width) and crops — scale/logical size in such shots are wrong. Use `pnpm e2e --grep @screens` (Playwright viewport emulation) for real shots.
- Sprites: generators write `buffer.set(x, y, { ramp, shade, alpha?, material?, normal?, partId?, depth? })` (defaults `PIXEL_DEFAULTS`; `get`/`inBounds` for neighbour passes); `quantize` picks ramp colors + Bayer 4×4 on fractional shades; RNG per frame seeded from `<atlas>:<frame name>` (golden test). Frame names `<entity>[.<variant>][@emissive|@shadow]/<anim>/<nn>` (types.ts). No raw Math.sin/cos/exp/pow/cbrt in generator output (engine-dependent last bits). Soft alpha only in `SOFT_ALPHA_ATLASES` (`fx`). `public/atlases/` is git-ignored → `pnpm dev`/`pnpm build`/e2e webServer run `pnpm sprites` first; it also writes `index.json` (render loads that list; `debug: true` atlases are dev/test only — `vite-atlases.ts` deletes them from production `dist/`, check:dist enforces). Atlases load before `app.init`; any load failure sets `body[data-ready="error"]` (e2e `waitReady` fails at once).
