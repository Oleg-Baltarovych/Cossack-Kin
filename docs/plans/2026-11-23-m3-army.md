## 0. Ключові рішення (архітектура; продуктові розвилки — Q-список §6)
- **Стан походу — дискримінований union у слоті** (core.md): `RaidSlot = { kind: 'idle' } | { kind: 'running'; raid: RaidRoll } | { kind: 'returned'; raid: RaidRoll }`, де `RaidRoll = { region: RegionId; tier: RaidTierId; startedAt; returnAt; success: boolean; rumor: boolean; loot: { ducats: Big; glory: Big; pysanky: number; relic: RelicId | null } }`. Усе, що гравець міг би перекинути перезавантаженням (успіх, писанки, реліквія), кидається **на старті** з `state.rng` (`next`) і зберігається; здобич у Big рахується на старті за `steadyModifiers` (Q4) — без вітру моменту, тож та сама хоч онлайн, хоч офлайн.
- **Час:** `returnAt` — абсолютна мітка (§3.8). `advance` додає точки розриву `returnAt ∈ (lastSeen, now]` → слот `running → returned`, подія `RaidReturned { slot, region, success }`. Похід не змінює ставок (армія не «йде» з економіки — Q1), тож розрив лише для події й переходу стану — інтеграл доходу не змінюється. `applyOffline` інтегрує дохід до `lastSeen + eff` (ліміт), а походи завершує до **реального** `now` (таймери не мають офлайн-ліміту; `forwardJump` — Q8). Годинник назад: `now ≤ lastSeen` → нічого (як зараз).
- **Дошка дня (§2.6):** не стан — `raidBoard(seed, day, village)` = для кожного тиру тривалості (5 хв / 30 хв / 1 год / 4 год / 8 год) регіон із пулу краю через `pickStable(hash32(seed, BOARD.salt), day)`; одна пропозиція дня — «чутка» (`+lootMult` або `+relicChance`, з контенту). День = `dayAt(maxSeen, tzOffsetMin)` (M2-23, монотонний). Що «використано» за день — Q3; якщо чутка разова, у стані лише `raids.rumorDay`.
- **Слоти:** `RAIDS.slots` = 2 у контенті; масив слотів у стані фіксованої довжини `RAIDS.maxSlots` (3: місце для слота за писанки M8b без ще одного bump), відкриті = похідна (`openSlots(state)` = 2 + 0 у M3; M4 «Чайки», M5 Родове дерево, M8b — додадуть). Слот понад відкриті завжди `idle` (validateState).
- **Формули (числа — `content/raids.ts`):** `P(tier, land)`; старт лише при `power ≥ RAIDS.minPowerShare (0.5) × P`; `chance = clamp(power / P, chanceMin 0.35, 1)`; дукати = `farmIncomeRate(steady) × lootSec[tier] × lootMult`, слава = `gloryRate(steady) × gloryLootSec[tier] × lootMult` (з мінімумом `REWARD.minPerMinute`, як у віх — щоб похід до першої будівлі не дав 0); невдача × `failShare` 0.3; писанки — шанс за тиром; реліквія — шанс за тиром × `relicChanceMult`, лише з незнайдених реліквій краю, + «запобіжник» першої реліквії (Q5). `lootMult` = 1 + скарбниця × `lootPerLevel` + реліквії; `raidTimeMult` (у M3 = 1; M4 Характерник) — уже в `Modifiers`.
- **Дії:** `startRaid { slot, tier }` (відмови: `slotBusy`, `power`, `range`), `claimRaid { slot }` (`notReturned`) → валюти, `relics`, `stats`; події `RaidStarted { slot, region, tier, returnAt }`, `RaidReturned`, `RaidClaimed { slot, success, granted, relic }`, `RelicFound { id }`. Як і з квестами: `RaidReturned` може прийти з часу (тік/офлайн), `RaidClaimed`/`RelicFound` — лише з дії.
- **GameState v4** (`/save-migration`, міграція `003-v3-to-v4.ts`, фікстура `v4.json` з `capture-save` з походом у польоті і поверненим):
  ```ts
  version: 4;
  raids: { slots: readonly RaidSlot[] /* length RAIDS.maxSlots */; rumorDay: number /* Q3 */;
           pity: number /* Q5: успішних кидків тиру ≥ RELICS.pityMinTier без реліквії; знахідка → 0 (M3-01: поля бракувало) */ };
  relics: readonly RelicId[];                          // порядок знахідки; невідомий id відкидається (як story.seen)
  stats: { …v3; raidsSent: number; raidsDone: number; raidsWon: number };
  ```
  Міграція: усі слоти `idle`, `relics` [], лічильники 0, `rumorDay` −1, `pity` 0; ланцюжок — Q7 (вставка кроку = зсув `index`). `validateState`: `startedAt ≤ returnAt`, `returnAt − startedAt ≤ max тривалості`, `startedAt ≤ maxSeen`, Big-межі здобичі, `relic` лише незнайдена, без дублів у `relics`, `raidsWon ≤ raidsDone ≤ raidsSent`, кількість `running|returned` ≤ `raidsSent − raidsDone`, `0 ≤ pity < pityThreshold(relics.length)` (`RELICS.pityAt` — масив за кількістю знайдених, після кінця — останнє; хелпер у `content/relics.ts`), `rumorDay ≤ dayAt(maxSeen, +840) + 1`.
- **Селектори (UI й рендер читають лише їх):** `raidSlotsView(state, now)` (стан, тир, регіон, `returnAt`, лишилось с — без шансу, рішення M3-06; **у `running` немає `success` і здобичі** — тип, §0.1 П4), `raidBoardView(state)` (пропозиції, P, шанс, здобич успіху й невдачі, шанс реліквії, `relicSure` — П5, причина вимкнення, сили до 100 %, чутка), `relicsView(state)`, `raidSceneView(state)` (для рендера: які слоти в дорозі/вернулися, без чисел економіки). Відлік таймера UI рахує від живого `now` (як HUD), core не тікає заради нього.
- **Рендер (косметика, лише події + селектор):** загін = наявні на сцені козаки (з бюджету 16, не понад) — нова роль-доручення `raid` для `squadSize` (контент, напр. 5) + отаман + корогвоносець; маршрут майдан → брама → за межу світу (вузли поза валом; точний маршрут вирішує art-director у M3-13, бо намальована брама в задній стіні — M2-16); поки похід триває — ці агенти `absent`; `RaidReturned` наживо → в'їзд зі скринею, 2–4 селяни з передмістя біжать до `sich.gate` і `cheer` (у Січ не заходять); якщо повернення сталося офлайн / до завантаження — загін уже вдома, скриня стоїть на майдані, доки не забрано (Q14). Отаман іде з першим загоном; другий слот — під корогвою без отамана.
- **UI:** вкладка «Січ» — блок «Походи» (картки слотів: вільний → «Обрати похід»; у дорозі → тир, регіон, відлік (без шансу — M3-06); повернувся → «Забрати», червона крапка на табі при згорнутій шторці); «Мапа» — повна шторка: згенерована піксельна мапа Низу Дніпра (DOM CSS-спрайт, як іконки) + маркери-кнопки регіонів дошки (≥ 44 css px), картка пропозиції (тривалість, P, шанс, здобич, чутка, причина вимкнення) → «Вирушити»; вікно результату — скриня (тряска → відкриття → предмети по одному; «менше руху» — одразу список), реліквія з назвою й фактом; вікно повернення — рядок «Походи: N повернулося» (з `raidSlotsView`, `ReturnReport` не змінюється); «Ще → Скарбниця» — реліквії (знайдені + силуети незнайдених). Вікна — у наявній черзі `GameUi` (після повернення й віх).
- **Квести:** `BUILD_SYSTEMS` += `'raids'`; `StatId` += `raidsSent`, `raidsDone`; справи «Відправ похід» / «Заверши 2 походи» (append у `CHORE_IDS`); крок ланцюжка — Q7.

Мапа Низу Дніпра (пороги, Хортиця, Великий Луг, степ, кургани; стиль — Q11) + маркери (5 тирів, чутка, «у дорозі») · козак a–c `march` 6@10 · корогвоносець idle/march + корогва 4 кадри вітру · скриня (проп + `@shadow`) і пара носіїв `march` · (наявні: отаман march, селяни cheer). Значки реліквій 16×16 у атласі `ui` (2–3, Q5) + силует «невідомо».

## 4. Баланс (M3-08)
- Порядок важелів (по одному): `lootSec`/`gloryLootSec` тирів → P тирів → шанси писанок/реліквій → (лише якщо коридор червоний) base/growth будівель.
- Ризик подвійний: здобич пришвидшує Розквіт (< 4 дні) і додає «дій» (старт + збір ×2 слоти ≈ +2–4 на сесію; S1 вже ~35 з 40). Ціль частки здобичі в дукатах — звіт, не гейт (≈ 5–15 %, рекомендація).
- Хвости M2: seed 7 (кузня S2 при вікні S3–S5) і S1 до 54 дій (seed 9) — перевірити після походів; якщо лишились — або вікно кузні S2–S5 (рішення власника), або записати як відомий хвіст.

## 5. Ризики · Поза обсягом
- R1 Ланцюжок заморожений «лише дописувати»: вставка кроку походу ламає індекси → міграція зсуву (Q7). R2 Подія `RaidReturned` з офлайну не має запускати парад/тряску (лише наживо) — тест бриджа. R3 Козаки в поході «зникають» зі строю — на малій армії (2–3) стрій порожніє: загін ≤ половини показаних. R4 Атлас `people` росте (march ×3 + 3 нові постаті) — заміряти в M3-13. R5 Мапа як великий DOM-спрайт на 3.5 dpr — та сама піксельна прив'язка, що в іконок (`pixelSnap`).
- Поза обсягом: реклама (прискорення, ×2) і стоки писанок (3-й слот, «завершити зараз», авто-збір) — M8; сповіщення «козаки повернулися» — M6; герої/культура, що змінюють походи — M4; гармаші/кіннота — M10+; морські походи — край 3; аудіо (фанфара, барабан) — M7; аналітика `raid_start/claim` — M9.

## 6. Питання до власника
**Рішення власника 2026-11-24: Q1–Q15 = рекомендовані дефолти нижче** (записано в SPEC §2.6/§3.4/§3.8/§9.3/§10/§12.3 і ADR 012 у M3-01):
- Q1 армія не «йде» — похід бере знімок сили, економіка не змінюється · Q2 без втрат, невдача = 30 % · Q3 5 пропозицій на день (по тиру), повтори без ліміту, чутка — на перший старт на ній за день · Q4 здобич фіксується на старті за сталим доходом · Q5 у M3 «Пернач» і «Порохівниця», без дублікатів, перша реліквія щонайпізніше на 4-му успіху ≥ 30 хв, усі знайдені → писанки · Q6 писанки 1–2 лише з походів ≥ 1 год, накопичуються · Q7 крок `khortytsia.raid1` після `hire1`, міграція зсуває `index` мовчки · Q8 перевод годинника вперед завершує походи — прийнято · Q9 збір вручну · Q10 колекція — «Ще → Скарбниця», значки біля сили на «Січ» · Q11 мапа на пергаменті кодом · Q12 ≈ 6 географічних регіонів Низу, ворог не названий · Q13 без сюжетної віхи за перший похід · Q14 повернення офлайн — без параду, скриня на майдані · Q15 тири відкриває лише сила.

### Вихідні формулювання (дефолт — рекомендація)
- **Q1** Чи «йде» армія в похід: козаки в дорозі не дають пасивної слави / сили для другого слота? → **Ні: похід бере силу всього війська як знімок, армія лишається вдома в економіці** (простий аналітичний офлайн, обидва слоти рівноправні); візуально йде лише загін.
- **Q2** Втрати в поході (SPEC мовчить)? → **Немає**: невдача = 30 % здобичі, козаки не гинуть (тон §16, без покарань §2.6).
- **Q3** Дошка дня: скільки пропозицій і чи можна повторювати? → **5 пропозицій на день — по одній на тривалість (5 хв…8 год), регіон за `hash32(seed, day)`; кожну можна запускати скільки завгодно разів; «чутка» — одна пропозиція дня, бонус діє на перший старт на ній за день.**
- **Q4** Здобич фіксується на старті чи рахується при поверненні? → **На старті** (за сталим доходом): що показано на мапі, те й прийде; не залежить від покупок під час походу.
- **Q5** Реліквії краю 1 і їхні правила? → **У M3 дві: «Пернач» (+5 % сили) і «Порохівниця» (+10 % здобичі); «Кобза діда» (−5 % ціни культури) — у M4 разом із культурою. Без дублікатів (кидок лише серед незнайдених); запобіжник: перша реліквія — щонайпізніше на 4-му успішному поході ≥ 30 хв (календар S2–S5).** Усі знайдені → шанс реліквії стає шансом писанки.
- **Q6** Писанки зі здобичі до появи магазину (M8)? → **Так, малий шанс (1–2 писанки) лише на походах ≥ 1 год; накопичуються й видно баланс** (як M2 Q10).
- **Q7** Онбординг §10 («… найми першого козака, відправ у розвідку») — крок «Наказу кошового» для першого походу: вставити чи дописати в кінець? → **Вставити `khortytsia.raid1` одразу після `khortytsia.hire1`** (S1 за календарем); міграція v3 → v4 зсуває `index` збережень, що вже далі (крок для них — мовчки виконаний, без нагороди).
- **Q8** Перевод годинника вперед завершує походи (і реліквії/писанки зі шансом)? → **Прийняти, як для справ (§3.9)**: гра одиночна, писанки зі здобичі рідкісні; захист — після M8 разом з рішенням про писанки в експорті (§9.5).
- **Q9** Збір здобичі вручну чи автоматично? → **Вручну** (дія «Забрати», слот зайнятий до збору); авто-збір — сток за писанки M8b (§4.2).
- **Q10** Де колекція реліквій? → **«Ще → Скарбниця»** (§10.3); у вкладці «Січ» — лише значки знайдених біля сили війська.
- **Q11** Стиль мапи регіонів? → **Стара мапа на пергаменті (вид згори, Дніпро з порогами, Хортиця, Великий Луг, степ із курганами), кодом у палітрі**; альтернатива — «вид із висоти» в стилі світу (дорожче).
- **Q12** Регіони й «ворог»? → **Лише географічні назви Низу (≈ 6: Пороги, Кінські Води, Тавань, Самара, Вовчі Води, Дике Поле), противник не названий і не показаний (§16)**; тексти — «розвідка», «застава», «переправа», без жорстокості.
- **Q13** Сюжетна віха за перший похід у краї 1 (таблиця §2.5 її не має)? → **Ні**: новинку дає крок ланцюжка (Q7) і перший похід/реліквія в календарі; віха `raidsWon` — для країв 3+.
- **Q14** Якщо похід повернувся, поки гру закрито, — показувати парад при вході? → **Ні**: загін уже вдома, скриня стоїть на майдані до «Забрати»; парад — лише коли повернення сталося на очах.
- **Q15** Тири тривалості відкриваються лише силою (≥ 0.5·P) чи ще й рівнями Січі? → **Лише силою**: похід 4 год стає доступним, коли військо доросло (календар S8 — результат балансу).

### Q16+ — нові розвилки з §0.1 (**вирішено власником 2026-11-24: усі Q16–Q21 = рекомендації**)
- **Q16** Запобіжник лише для першої реліквії (Q5) чи для кожної? → **Для кожної реліквії краю**: `raids.pity` скидається на знахідці, `RELICS.pityAt` 4 для першої, далі з контенту (≈ 6); інакше «Порохівниця» може не прийти тижнями. Поле `pity` потрібне й за Q5 — v4 однаковий за обох відповідей.
- **Q17** «Забрати все» при ≥ 2 повернених походах? → **Так**: одна кнопка = `claimRaid` по кожному слоту (у §12.3 — по дії на слот), одне вікно скрині з підсумком; не авто-збір (той лишається стоком M8b).
- **Q18** Сповіщення «козаки повернулися» (M6): як групувати й коли просити дозвіл? → **Повернення в межах 30 хв — одне сповіщення; не частіше 2 на день (§3.9); запит дозволу — після першого поверненого походу, не на старті; тихі години 22:00–08:00 переносять на 08:00.** У M3 — лише чистий `raidAlerts` і mock-сервіс.
- **Q19** Перший похід — гарантований успіх? → **Так, через P тиру 5 хв ≤ сили 1 козака** (без окремого правила; розвідка 5 хв лишається «легкою» назавжди); альтернатива — правило «перший похід = успіх» у core.
- **Q20** Якщо походи виштовхнуть `s1Actions` понад 40? → **Стелю не піднімати**: спершу тюнінг (P/тривалість першого кроку, крок `raid1` замість окремої справи); підняти до 45 — лише вашим рішенням після звіту M3-08.
- **Q21** Шанс реліквії на картці — точний % чи словами («рідко / інколи»)? → **Точний %** (чесність §0.1 П3; той самий принцип, що в шансі успіху), запобіжник — окремим рядком «реліквія близько».
