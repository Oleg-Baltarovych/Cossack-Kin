## 0. Ключові рішення
- **Сигнатура часу:** `advance(state, now) → { state, events }` інтегрує від `state.time.lastSeen` до `now` без ліміту; `dt` не передається окремо (дві джерела правди про час → баг). `tick(state, now)` = `advance`, якщо `now − lastSeen ≤ onlineGapSec` (content), інакше → `applyOffline`. `applyOffline(state, now)`: `now < lastSeen` → 0 доходу, `lastSeen = now`; `eff = min(now − lastSeen, offlineCapSec)`; стрибок понад `maxSeen + forwardJumpCapSec` (7 д) → рахується як ліміт; інтегрує `advance` до `lastSeen + eff`, решту часу пропускає без доходу (`lastSeen = now`, `maxSeen = max`). SPEC §3.8 і ADR 002 (amendment) оновлюються в M1-21; `.claude/rules/core.md` правити lead-developer (поза `docs/`).
- **Кусково-аналітично:** у M1 рівні змінюються лише діями, тож дохід усередині `advance` — кусково-сталий; точки розриву = зміни вітру (Q2). Відрізок: `ducats += rate(seg) × dur`, `glory += min(gloryRate × dur, cap)`. Жодного покрокового циклу.
- **GameState v1 (лише поля M1; майбутні поля = bump + міграція, YAGNI):**

- **Вікно повернення:** офлайн-дохід кладеться в `returnReport` (зберігається), а нараховується дією `claimReturn` — так M8 зможе додати `claimReturn({ double: true })` після `rewarded` без перерахунку. Новий `applyOffline` при незабраному звіті спочатку зараховує старий. Звіт показується, якщо `awaySec ≥ returnMinSec` (content).

- **Формули (§3.2):** `cost(l) = base × scale × g^l × costMult`; купівля n рівнів — геометрична сума `base·scale·g^l·(g^n−1)/(g−1)`; MAX — замкнена формула через `log` + перевірка ±1; ×10/×25 купують рівно n (або залишок до max рівня), інакше кнопка вимкнена. `prod(l) = baseProd × scale × l × milestoneMult(l) × prodMult`. Тір = кількість пройдених віх (0–5 хутір, 0–3 Січ). Харч, оборона, `maxCossacks`, тап — §3.0/§3.3, коефіцієнти в контенті.
