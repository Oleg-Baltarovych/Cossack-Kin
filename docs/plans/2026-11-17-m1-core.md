## 0. Ключові рішення
- **Сигнатура часу:** `advance(state, now) → { state, events }` інтегрує від `state.time.lastSeen` до `now` без ліміту; `dt` не передається окремо (дві джерела правди про час → баг). `tick(state, now)` = `advance`, якщо `now − lastSeen ≤ onlineGapSec` (content), інакше → `applyOffline`. `applyOffline(state, now)`: `now < lastSeen` → 0 доходу, `lastSeen = now`; `eff = min(now − lastSeen, offlineCapSec)`; стрибок понад `maxSeen + forwardJumpCapSec` (7 д) → рахується як ліміт; інтегрує `advance` до `lastSeen + eff`, решту часу пропускає без доходу (`lastSeen = now`, `maxSeen = max`). SPEC §3.8 і ADR 002 (amendment) оновлюються в M1-21; `.claude/rules/core.md` правити lead-developer (поза `docs/`).
- **Кусково-аналітично:** у M1 рівні змінюються лише діями, тож дохід усередині `advance` — кусково-сталий; точки розриву = зміни вітру (Q2). Відрізок: `ducats += rate(seg) × dur`, `glory += min(gloryRate × dur, cap)`. Жодного покрокового циклу.
- **GameState v1 (лише поля M1; майбутні поля = bump + міграція, YAGNI):**
  ```ts
  type VillageId = 'khortytsia' | 'velykyi-luh' | … ;                 // усі 8 з §9.3
  type KhortytsiaBuildingId = 'field'|'garden'|'apiary'|'windmill'|'potter'|'smithy'|'tavern'|'fair';
  type SichBuildingId = 'kurins'|'maidan'|'walls'|'treasury'|'church'|'cannonry'|'special';
  type WindLevel = 'calm'|'breeze'|'storm';
  type VillageState =                                                 // дискримінований за id
    | { id: 'khortytsia'; levels: Record<KhortytsiaBuildingId, number>; sichLevels: Record<SichBuildingId, number>;
        lifetimeDucats: Big; mechanic: { kind: 'wind'; stormsSurvived: number } };
  interface GameState { version: 1; seed: number; rng: { state: number };
    time: { lastSeen: number; maxSeen: number; created: number };
    currencies: { ducats: Big; glory: Big; regalia: number; pysanky: number };
    village: VillageState; army: { infantry: number };               // army — лише якщо Q1 = так
    returnReport: ReturnReport | null; stats: { taps: number; purchases: number };
    settings: { lang: 'uk'|'en'; numberFormat: 'words'|'short' } }
  type ReturnReport = { awaySec: number; countedSec: number; capped: boolean; reason: 'normal'|'clockBack'|'forwardJump';
    ducats: Big; glory: Big };
  ```
  Похідні (не в стані): `kharch`, `maxCossacks`, `defence`, `tier`, `wind(t)`, «відкрито» для Січі. Заблокована будівля Січі = рівень 0 + предикат відкриття з контенту.
- **Вікно повернення:** офлайн-дохід кладеться в `returnReport` (зберігається), а нараховується дією `claimReturn` — так M8 зможе додати `claimReturn({ double: true })` після `rewarded` без перерахунку. Новий `applyOffline` при незабраному звіті спочатку зараховує старий. Звіт показується, якщо `awaySec ≥ returnMinSec` (content).
- **RNG:** `core/rng.ts` mulberry32, стан `rng.state` (uint32) у `GameState`; `next(rng) → [value, rng']` без мутацій. Розклади (вітер) — не з курсора, а `hash32(seed, windowIndex)` (чиста функція часу, §3.8). Seed нової гри приходить ззовні (`platform` → `crypto.getRandomValues`), core його не генерує.
- **Big:** `core/big.ts` — єдиний імпорт `break_eternity.js`; непрозорий тип `Big` + функції (`add`, `mul`, `pow`, `log`, `cmp`, `fromString` строгий, `toString`); ніде в core немає `Decimal` напряму (ESLint `no-restricted-imports` поза `big.ts`). У збереженні — рядок.
- **Формули (§3.2):** `cost(l) = base × scale × g^l × costMult`; купівля n рівнів — геометрична сума `base·scale·g^l·(g^n−1)/(g−1)`; MAX — замкнена формула через `log` + перевірка ±1; ×10/×25 купують рівно n (або залишок до max рівня), інакше кнопка вимкнена. `prod(l) = baseProd × scale × l × milestoneMult(l) × prodMult`. Тір = кількість пройдених віх (0–5 хутір, 0–3 Січ). Харч, оборона, `maxCossacks`, тап — §3.0/§3.3, коефіцієнти в контенті.
- **Модифікатори (§9.6):** мінімальний `collectModifiers(state, now)` уже в M1 (оборона → `incomeMult`, вітер → множник вітряка, «Вітряки ×2», шинок → `gloryMult`, кузня/майдан → сила, скарбниця → ліміт слави). Системи не читають будівлі-бафи напряму. Кеш — ні (заміряти; додати лише якщо tick > бюджету).
- **Store (§9.2):** `createStore(initial)` у core: `getState`, `dispatch(action, now)`, `tick(now)`, `subscribe(listener)` (для `useSyncExternalStore`; новий об'єкт стану на кожну зміну), `onEvent(listener)`. Події — дискримінований union: `BuildingUpgraded`, `TierReached`, `SichUpgraded`, `CossackHired`, `Tapped{amount}`, `ActionRejected{action, reason}`, `WindChanged{from,to}`, `OfflineApplied{report}`, `ReturnClaimed`, `StateReplaced` (load/reset). ## 5. Відкриті питання до власника (дефолт — рекомендація)
- **Q1** Звідки слава в M1? Без неї Січ не купити, а Розквіт вимагає Січ ≥ 25. → **Перенести з M3 найм піхоти + пасивну славу (без походів)**; M3 лишається походи, реліквії, вихід загону.

- **Q4** «Церква: край 1, Розквіт ≥ 25». → **Відкривається, коли всі господарські ≥ 25**.
- **Q5** Пушкарня (край 5) у краї 1 → **визначена в контенті, прихована в UI**; «7 будівель» = 6 відкриваних.
- **Q6** Розквіт у симуляторі M1 → **умови 1–2 + 3 бурі**; кнопка й переселення — M5.
- **Q7** `offlineMult` базовий і поріг звіту → **1.0 і 60 с** (ліміт 8 год, §3.8).
- **Q8** Ліміт тапів → **10/с**, понад — ігнор без події.
- **Q9** Web-сховище в M1 → **localStorage**; Preferences — M9.
