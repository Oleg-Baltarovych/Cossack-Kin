## 0. Ключові рішення
- **Розбиття (Q1):** M2 ≈ 139 год ≈ 1.9× M1 (73.5) → рекомендую **M2a «Селище»** (світ, камера, усі тіри, будівництво, bottom sheet, UI-перенесене; ≈ 71 год, без зміни схеми збереження) і **M2b «Життя й історія»** (агенти, вози, мандрівники, віхи, квести, save v2, джус, баланс, перф; ≈ 68 год). Кожна половина має своє приймання; AC 5–6 — лише M2b.
- **Неперервний світ:** один `KHORTYTSIA_WORLD: WorldLayout` замість `KHORTYTSIA_ZONES` — зони як x-проміжки (`zones: { id, x0, x1, anchorX }[]`), смуги ґрунту й далекі плани по сегментах із перехідними тайлами; той самий горизонт 0.42. Ширина — Q2 (дефолт ≈ 1800 px). `?zone=` стає позицією камери (`anchorX`), а не вибором сцени. Далекий план зшивається за паралаксом (ширина = world × 0.2 + view). Рендер-рішення фіксуємо ADR 011 (architect, після спайка M2-01).
- **Атласи (§12.4):** «один атлас на край ≤ 2048² + спільний для людей і UI». M2-01 міряє поточний `khortytsia` і бюджет тірів; дефолт — `khortytsia` (будівлі, ґрунт, пропси), `people` (селяни, козаки, вози, мандрівники), `ui` (іконки, DOM), `fx` (м'яка альфа). Кількість draw calls при змішаних атласах міряємо (батчинг Pixi v8 за кількома текстурами перевірити в спайку на `__CK__.stats.drawCalls`, не з пам'яті); якщо > 30 — сортування за атласом у межах Y-смуги.
- **Тіри — модульно (art.md):** генератор будівлі пише `<entity>.t1…t6` (Січ `t1…t4`) з однієї основи + додатки; спільні додатки (тин, мальви, рушник, стяг, глечики) — окремі пропи з `plot { from, until }`, як у M1-19. Проп `tierSprite: { building, frames: Record<tier, stem> }` замість ручних пар `from/until` для кожного тіру.
- **Варіанти (§2.6):** core-селектор `plotVariant(seed, plotId) = hash32(seed, plotIndex) mod n` (n із контенту) → косметичний варіант (мальви/соняшники/рушник/колір дверей/розпис). Без стану: варіант — функція сида.
- **Камера (render/input, без бібліотек):** pointer events → чиста `camera/motion.ts` (тяг, інерція з експоненційним загасанням, межі, «плавний переїзд» до `anchorX` з easing) — test-first; pinch = 2 цілі рівні масштабу (Q4); подвійний тап — центр на точку; таб «Хутір»/«Січ» везе камеру (UI → `world.focusZone(id)`); «менше руху» → миттєвий стрибок. Тап vs тяг: поріг у логічних px. Тап по будівлі → hit-test ділянки → bottom sheet з її рядком (§3.3).
- **Агенти — косметика в рендері (ADR 002: економіка аналітична):** `render/entities/` — пул агентів, граф стежок з даних (`villages/khortytsia.paths.ts`: вузли з тегами `work:<id>`, `poi:well|fair|tavern|bench`, `fire`, `home`, `gate`, `maidan`; ребра з `zone`; ребер Січі для селян немає), BFS. FSM — чисті функції `step(agent, dt, ctx) → agent` з фіксованим кроком 1/30 с і косметичним RNG `render/clock.ts`; під `?freeze` — детермінований розігрів до `FROZEN_NOW` (знімки стабільні). Розклад дня — від годинника доби. Кількість — core-селектор `populationView(state)` (селяни за Σрівнів, козаки = min(піхота, ліміт показу), частота возів ~ харч) з таблиць `content/life.ts`; таймінги FSM — `render/entities/config.ts` (косметика, як `atmosphere/config.ts`). Люди ходять і під «менше руху» (§6.3).
- **Мандрівники:** розклад — чиста core-функція `visitorAt(seed, t)` (слоти, як вітер; `content/visitors.ts`), бо M6 додасть баф; у M2 рендер лише читає. Не стан, не офлайн.
- **Віхи (§2.5):** `content/story.ts` (`StoryBeat`, `StoryTrigger` §2.5), `core/systems/story.ts`: після кожного `advance`/дії перевіряє невидані тригери (монотонні), нараховує нагороду в момент спрацювання, пише `story.seen`, подія `StoryBeatReached { id, reward }`. У M2 — лише тригери, що є в збірці: `start`, `building|sich`, `hired`, `storms`, `bloom` (Q7). Нагорода — спільний `Reward` з квестами: `{ kind: 'incomeMinutes'|'gloryMinutes'; minutes } | { kind: 'pysanky'; n }` = хвилини × поточна швидкість (мін. поріг у контенті).
- **Квести (§3.10, лише ланцюжок і справи):** `content/quests.ts`; ланцюжок краю 1 ~25–30 кроків у порядку календаря §2.4, далі генерований «підніми найближчу будівлю до наступної віхи»; справи — пул ~8, наступна = `hash32(seed, chores.n)` серед доступних (`requires`), ≤ `CHORES.maxClaimsPerDay` (10) нагород на день, далі лише лічильник. Виконання — похідне (`stats` − `base` ≥ n або рівень ≥ l), забирання — дія `claimQuest({ kind })`, події `QuestCompleted`, `QuestClaimed`. «День» — §3.9 від `maxSeen` у локальному поясі (Q9).
- **GameState v2 (M2b; /save-migration):**
  ```ts
  version: 2;
  story: { seen: StoryBeatId[] };
  quests: { chain: { land: VillageId; index: number; base: number };       // base — стат на старті кроку (count-цілі)
            chores: { day: number; n: number; active: ChoreId; base: number; claims: number } };
  stats: { taps; purchases; levelsBought: number; hires: number; tapIncomeSec: number };
  settings: { lang; numberFormat; tzOffsetMin: number };                    // Q9
  ```
  Міграція v1 → v2: `seen` = віхи з уже виконаними тригерами (мовчки, без модалки й нагороди — §2.5); ланцюжок — перший невиконаний крок (виконані мовчки пропускаються без нагороди — та сама логіка, що для віх); `levelsBought` = Σрівнів (у M1 скидань немає), `hires` = піхота, `tapIncomeSec` = 0; справи — свіжі. Щоденні/тижневі — M6 (ще один bump, ADR 009).
- **Події для рендеру й UI:** наявні `BuildingUpgraded` (0 → 1 = будівництво), `TierReached` (спалах, банер, стяг), `CossackHired` (козак виходить із куреня), `ReturnClaimed` (монетки до лічильника); нові `StoryBeatReached`, `QuestCompleted`, `QuestClaimed`. Рендер не імпортує actions (ESLint `imports[render-actions]` уже є).
- **Джус і піксельна сітка (Q5):** squash 1.0 → 1.08 → 1.0 — масштаб у low-res RT з округленням розміру до цілих px і nearest (рядки дублюються, сітка ціла), лише ≤ 200 мс; конфеті, пил — частинки через `claimParticles` (бюджет 300 разом з атмосферою). Тряска камери 2 px/150 мс лише на тірі VI, віхах і Розквіті; «менше руху» вимикає.
- **Бандл:** `ui/App.tsx` вантажить `render/index.ts` через `import()` — оболонка й HUD до Pixi; світ з'являється за `data-ready`. Атласи як і раніше до `app.init`.
